# CTLA4 V4.1 空推荐修复审计

## 原始故障证据

最新运行 `workspace_data/8c068ad701a6`（2026-09-30，P16410）为
`BLOCKED_EXTERNAL_EVIDENCE`，候选数和正式面板数均为零。

1. `.venv/Scripts/python.exe` 继承了 Windows Low Mandatory Level。该解释器
   启动的 WSL 返回 `Wsl/E_ACCESSDENIED`；正常用户运行的系统 Python 和
   PowerShell 可启动同一发行版。旧 `wsl_bridge.py` 只读 stderr，但 WSL
   将实际错误放在 UTF-16LE stdout，结果 manifest 仅留下空的 RuntimeError。
2. ProCaliper worker 从不存在的 `Bio.PDB.Select` 模块导入 Select。
   实际安装的 Biopython 将其从 `Bio.PDB` / `Bio.PDB.PDBIO` 导出。
3. 前一次 `workspace_data/e66fb47e803d` 中，SPURS single、DiscoTope 和
   FoldX 均成功，SPURS multi 因 `Duplicate SPURS multi combination` 整批失败。
   210 条候选中有 5 个重复组合跨越不同显示区域，例如同一
   K65W/A66W/N93C 来自 C074_A0600 和 C033_A0600。原搜索只在区域内去重。

更早的 `5bfbaac5cc03` 存在 25 个 CONSENSUS_PASS 候选和 7 个正式入选组合。
本次空结果不能据此解释为 CTLA4 没有可用候选。

## 修改

- `candidate_search.py` 在全局合并物理相同的组合，保留其所有 footprint
  归属；显示 anchor 不参与组合的物理身份。
- `engine._prediction` 对组合请求再次规范化和去重。SPURS 的重复输出、
  缺失输出、WT 不符和非有限数值检查继续保留。
- 同一搜索窗口复用单位置测地距离和同一位置集合的覆盖结果。
  氨基酸菜单变化不改变空间覆盖；减少重复计算，不改变科学门槛。
- 修正 ProCaliper 的 Select 导入。
- 桥接程序使用 argv 和 `--exec`，保留含空格路径；解析 UTF-16LE 的 WSL
  stdout 错误和 UTF-8 worker stderr，返回结构化错误码、发行版、操作与退出码。
- 标准化结构的 native SASA 审查始终执行，不再依赖可选 ProCaliper 成功。
- SPURS multi 先评分，FoldX 有限预算用于通过 SPURS 主候选门槛的组合。
  四点探索候选不消耗主面板确认预算。
- 没有候选或没有可确认候选时，报告明确的未执行原因，避免空失败记录。
- 新增 `recommendation_diagnostics_v41.json`，保存候选数量、唯一组合数、
  正式通过数、排除原因计数、worker 故障和失败阶段。
- analysis、科学报告和任务完成消息保留推荐阻断原因；V4.1 文件进入
  `run_manifest.json` 的校验和清单及下载 ZIP。

`WSL_ACCESS_DENIED`，应检查新启动程序的标签与进程身份。worker 不自动
提升权限或修改系统安全设置。
