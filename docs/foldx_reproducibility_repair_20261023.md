# FoldX批次依赖与推荐解释修复（2026-10-23）

## 已完成修改

- `stability.score_many_with_foldx`统一为每个具体组合一个原生进程，组合内部按链/位点/替换固定排序；并发只改变任务调度，不把多个候选放进同一个采样流。仍保留既有并发和模型次数上限。
- 每次BuildModel显式记录timeSeedRotabase开关，冻结原始有序突变列表、实际修复输入、二进制/rotabase身份、命令与输出hash，保存stdout/stderr。worker按调用保存请求、原始结构、四份执行源码快照及执行清单。
- 新执行布局版本为`candidate_isolated_v1`。缓存核对worker/数值代码、输入、修复产物、rotabase和采样协议；旧布局或缺执行收据的缓存明确跳过，不能自动升级。
- 默认确定性协议必须复用一个完整原生调用，不能拼接不同批次或重启采样流补后缀；这类不完整缓存重新生成完整集合并记录真实成本。时间播种协议保留固定槽位1→3→5追加，拒绝重复槽或混入不同协议。
- 保持既定SPURS/FoldX中位数门槛。增加逐槽门上/门内数量、范围、完整性和采样敏感诊断。旧E59Y/K65F的两槽超限被明确展示为`SAMPLING_SENSITIVE_REVIEW`；UI不再无条件显示低风险。未知重复证据保留未知。
- 普通最终导出和选板重放共用来源证据打包，包含原始模型/表、输入、映射、命令和已有源码快照；使用包内相对路径、可移植配对清单及hash。历史没有记录的CLI/种子/源码保持UNKNOWN。物理证据归档同时收录执行收据与rotabase并按批次共享，避免逐槽复制大资产。

## 保留边界

固定证据的严格重放与新的时间播种采样是不同操作。新随机采样仍可产生数值波动，本修复阻止批次邻居暗中改变同一原生调用、缺来源或用单一中位数掩盖已知分散；不承诺不同随机采样逐字节相同。

本轮不自动扫描合并所有历史任务来推断跨执行冲突，不改变稳定性准入门槛，不据此证明实验折叠/表达。没有重启正在运行的服务；新worker每次子进程加载修改，已加载的主服务报告/导出代码需要正常重载后生效。未跑全仓测试或真实浏览器交互验收。
