# Joint V4 验证与比较方案

## 目标与当前证据状态

本方案比较相同输入、相同实验场景和相同构建体预算下，Surface V2、Joint V3 与 Joint V4-ML 选中突变位点命中已知抗体接触残基的能力。`benchmark_panels.py` 只实现结构接触位点代理终点；仓库目前没有按本方案整理的真实标签数据，也没有前瞻结合、表达或膜展示数据，因此不能报告 V4 优于成熟方案的经验结论。

## 数据集与冻结规则

1. 先定义抗原、抗体、ECD 坐标、结构/链、测定场景和接触标签。接触标签应来自可核查的抗原–抗体复合物结构，并事先固定重原子距离阈值、缺失残基处理和 UniProt 映射规则。
2. 按抗原家族划分开发集和冻结测试集；同一家族的所有抗体放在同一侧。结构同源体和同一抗体变体也须同侧，避免先验或调参泄漏。
3. 在冻结集解盲前，固定代码提交、依赖和模型摘要、所有科学阈值、结构选择规则、随机种子、主终点及排除标准。不能在测试集上选择最有利的配置。
4. 对每例用完全相同的序列、ECD 区间、结构 SHA-256、链、`assay_format` 和最多 7 个主构建体运行三种引擎。工具失败或没有正式面板的病例仍纳入分母并记零命中，同时报告失败率和预算不足率。

## 可执行的结构接触代理评估

建立 UTF-8 JSON 清单，例如：

```json
{
  "construct_budget": 7,
  "cases": [
    {
      "antigen_id": "ANTIGEN_1",
      "antigen_family": "FAMILY_1",
      "antibody_id": "ANTIBODY_1",
      "split": "frozen_test",
      "true_contact_positions": [42, 45, 89],
      "runs": {
        "surface_v2": "runs/v2/analysis.json",
        "joint_v3": "runs/v3/analysis.json",
        "joint_v4_ml": "runs/v4/analysis.json"
      }
    }
  ]
}
```

`runs` 路径相对于清单文件。运行：

```powershell
.\.venv\Scripts\python.exe -m ecd_epitope_scanner.benchmark_panels .\benchmark_manifest.json --split frozen_test --bootstrap-draws 2000 --output .\benchmark_result.json
```

脚本核对三种运行的 ECD 序列/范围、结构摘要和测定场景，拒绝同家族跨数据划分。主代理终点是每例前 7 个推荐构建体中，是否至少有一个被突变的残基与真实接触集合重叠；次终点为至少两个不同接触残基命中、平均构建体数和预算不足率。V4 `BLOCKED_EXTERNAL_EVIDENCE` 或 preview 计为零命中。输出包含按抗原聚类自助采样的区间和逐例配对的 V4−基线差值。置信区间只反映样本抽样不确定性，不消除结构标签偏差。

**解释限制：**接触残基被突变不等于抗体结合下降；没有命中也不等于表位未被扰动。比较结果不能替代直接功能实验。应同时报告标签结构的分辨率、抗原构象、糖基化及标签可映射比例。

## 消融与稳健性

在开发集预先固定以下消融，再在冻结集只执行一次：移除 DiscoTope 排序、移除 ProCaliper 一致性门控、仅 SPURS 稳定性、禁用三/四点组合、改变测地覆盖半径。每项保持 7 构建体预算、相同结构和相同筛选失败计分。对抗原家族、ECD 长度、糖基化密度、结构类型与 `cell_surface`/`purified` 场景分层报告，但这些分层分析应标记为探索性。

## 前瞻湿实验验证

在冻结预测后，盲法合成三引擎推荐的去重构建体与 WT，并加匹配数量的随机表面突变阴性对照和已知破坏折叠的阳性对照。每个构建体至少在独立制备批次中重复；随机化孔位与测量顺序，记录失败构建体。针对细胞表面测定，先验证总表达与膜展示，再用构象敏感对照抗体或配体评估折叠，最后测目标抗体结合；纯化蛋白另做纯度、聚集和热稳定性质量控制。实验前预注册结合下降阈值、表达合格阈值、排除规则、主比较、样本量依据与统计模型。主实验终点应是**在表达/折叠合格前提下的抗体结合下降率**，并报告所有合成失败与质量失败，不把它们事后删去。

只有完成此类配对验证，才能对面板的真实定位效率、构建体成本和与既有方法的优势作经验判断。
