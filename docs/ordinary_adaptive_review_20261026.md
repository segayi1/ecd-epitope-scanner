## 已复现并修复

1. 严格模式在 `display_candidates` 尚未赋值时读取它，触发 `UnboundLocalError: cannot access local variable 'display_candidates' where it is not associated with a value`。精简面板与显示统一要求正式科学门通过及组合模型通过。
2. 队列先用 SPURS 预扫整池，再做 FoldX，且移除失败行后继续递增偏移会跳过下一候选。现按各原则当前队首交错执行两个模型阶段，共享物理组合结果但不越过更靠前的未验证候选；技术错误阻断后续相关调用。
3. 规范化结构编号与原序列编号混用。模型请求用规范编号，返回给调度前映回原编号，送入既有稳定性注释前转换回规范编号，避免二次映射；端到端覆盖原编号从 1 与 101 开始的抗原及 binder。
4. 模型通过不能替代正式科学门。FoldX 通过后先执行正式科学门，失败则继续当前原则队列，不用不合格项填充推荐。
5. SQLite 物化丢失 `risk_components` / `impact_evidence`，会丢失三点增益等科学证据；现保留并恢复。完成态不再被 pending 行派生状态覆盖。
6. 自适应运行结果含 tuple 字典键，直接写诊断 JSON 失败。诊断只写可序列化账本；索引连接在 `finally` 中关闭。
7. 不同候选复用 `foldx_adaptive/slot_00`，会覆盖配对清单。改成 `foldx_adaptive/<candidate_id>/slot_00`，追加槽仍在同候选目录下独立记录。原始配对、模型阶段与来源证据保留。
8. 旧推荐构造器重排队列赢家并去掉表位原则。展示现按账本完成态选择各原则首个通过项，同一组合合并原则标签，缺口保留队列状态，binder 表位原则明确不适用。
9. ZIP 原先包含保存全部候选的 SQLite。公开文件登记与 ZIP 清单现只包含执行账本，不包含整个索引；用实际 ZIP 和 manifest 的 sentinel 回归验证。
