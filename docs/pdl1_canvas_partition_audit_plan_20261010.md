### 3.1 任务和结构资源没有失败

真实任务API、ECD CIF和energy PDB均HTTP 200；API严格JSON解析通过。不是原始结构文件缺失，也不是NaN/Infinity破坏JSON。

**本次没有稳定复现用户原来的“无法载入画布”。以下两项确实是缺陷，但不能单独宣称就是当时故障的已证明根因。**

### 3.2 每次载入启动两个并发Molstar实例

`web/app.js`的`adoptResult()`调用`renderAll()`；`renderAll()`默认已调用`ensureViewers()`，随后`adoptResult()`又调用一次。

浏览器运行时记录每次创建两实例，间隔13.5–16.8ms，render重叠、CIF请求重复。`web/renderer.js`的`init()`清空宿主并覆盖模块级plugin，但没有dispose旧实例。共享plugin及ready状态存在交叉读取风险。

## 4. 分区算法当前实际流程

```text
合格表面残基与收缩表面图
  → 固定请求数的k-center种子（默认7）
  → 最近中心归属与minimax-medoid迭代
  → 超径/不连通组按最小残基编号贪心拆分
  → 可行整块合并
  → 只修复不足4残基或50 Å²的小区
  → 公共返回前完整硬验收
```

### 4.1 最小大小修复没有实现大小偏好

先前1–2残基漏出的缺陷已经修复：当前公共返回门强制4/50/连通/26/18。此次小区不是再次漏过这个门。

当前代码没有10–15个残基目标，medoid优化距离而非人数，4–9残基合法区域不会继续调整。拆分从最小编号贪心生长，容易留下残片；整块并集超径时停止，即使边界调整可能改善。回溯返回首个可行方案，也不比较大小平衡。

因此本次碎片来自三个因素：现有空间尺度的客观限制、缺少大小偏好、局部贪心选择。

### 4.2 当前尺度下每区十多个残基确实不可实现

以当前保存图与原坐标建立冲突图：两点Cα距离>18 Å或图距离>26 Å，便不能同区。精确最大冲突团为13个节点：

`24、31、61、69、83、90、121、139、148、172、178、186、232`

78对节点都不能同区，故至少需要13区。另有完整合法13区重放见证，因此**当前图和阈值下最少区数恰为13**。

- 每区至少8个就不可能：13×8=104>103。
- 每区至少10个更不可能：13×10=130>103。
- 即使只看Cα18 Å，也至少需要12区，仍不能使所有区≥10。
- 14区不是最少，但降低到13区也无法完成全区10–15。

这限定于当前图、坐标及显示合同；不是蛋白真实连续表面的普适物理定理。

### 4.3 距离和“连通”需要明确解释

`joint_design/surface_units.py`的边由显式溶剂表面点邻接支撑，权重使用Cα距离，还包含76个非合格表面transit残基的收缩及35条序列补桥。因此这是残基表面图距离代理，不是精确的连续表面测地。

- 一个分区内不要求序列编号相邻；序列远隔的残基可以在三维结构中邻近。
- 收缩图连通不保证有色原子表面完全没有灰色缝隙；非合格transit残基可能成为连接路径。
- 当前直径使用全图最短路径，连通性使用本区诱导图。两种定义当前自洽，但不能混为一项。
- VS010全图距离25.518 Å，本区内部路径直径26.660 Å。若额外要求所有路径都在区内且≤26 Å，约束会更严格，分区可能更多。
- `bounded()`在缺失Cα时跳过对应距离检查，是公共入口的防御缺口；需验证完整三维有限坐标。本次103节点全部有效，这不是本次小区根因。

## 6. 建议修改计划

### A. 优先修复画布生命周期和结果载荷

1. `adoptResult()`用现有`renderAll(false)`，仅一次启动画布；普通面板刷新不重新创建插件。
2. `renderer.js`统一dispose旧实例；任务切换清除ready，并使旧异步加载不能更新新任务。waitReady针对当次实例而不是可能已被覆盖的共享引用。
3. 分阶段报告请求、解析、WebGL初始化、着色、定位、tooltip异常；辅助操作失败保留已载入的结构。提供重试，诊断中记录任务ID、资源、HTTP状态和具体阶段。
4. 复用已有pair诊断外置助手，保留完整审计文件、SHA256及ZIP。随后对首屏不使用的全候选池与重复来源采用文件引用/按需加载。
5. 保持现有API路由及完整结果可获取。正式网页使用轻量展示投影；如需投影请求参数，完整返回保持默认行为，不破坏旧API调用者。正式/离线共用展示字段与渲染器，不能通过丢弃证据来缩小数据。

### B. 将目标大小和空间尺度分开配置

1. 明确目标12个、偏好10–15个合格表面残基；保护残基仍计入分区归属，可突变位点数另列。
2. 连通、唯一覆盖、坐标有效、至少4残基/50 Å²及选定距离上限保持硬约束；10–15作为优化目标，不直接改成全输入都必须达到的硬门。
3. 推荐将30/22作为“接近每区十多个残基”方案的候选显示尺度，先通过边界优化和CTLA4/PD1几何回归后决定是否采用。它是显示紧凑性的调整，不是已验证抗体作用范围。未经下一步实施确认不改变现26/18默认。
4. 若选择保留26/18，则接受本PD-L1至少13区，实际大小通常较小；不能同时承诺全区10–15。
5. 距离上限固定后，搜索不能为凑人数自动扩大距离，不能删除困难残基或低置信度资格规则来改变分母。

### C. 复用现有分区器，增加平衡与方案选择

1. 初始中心数由合格节点数/目标12及图分量确定；固定7仅保留为兼容软偏好。用少量确定性中心起点比较，包含已知可行基线，不增加随机性。
2. 在已有小区硬修复后，对所有偏离10–15的合格区域继续优化：单残基边界迁移、双向交换、必要的两个或少量相邻区重建/吸收。每一步同时检查供体和受体的连通、直径、面积、覆盖及最小大小。
3. 用明确排序比较完整方案：首先满足全部硬约束；然后降低10–15范围之外的平方偏差，再比较与12目标的偏差、区数及空间紧凑性；最终以稳定残基集合排序破同分。避免人为权重掩盖硬约束。
4. 小区修复与平衡共用累计100,000搜索状态；增加状态去重，避免同一分配因节点顺序反复搜索；仅完整且更好方案原子提交。
5. 硬约束未满足时继续异常终止设计；已获得有效分区但优化预算耗尽时保留该方案，明确“优化未完成/未证明最优”，不能把它称无解或称已达理想大小。
6. 记录全图距离、本区路径距离和收缩路径解释；本轮保留当前全图直径合同，不默默新增更严格的内部路径上限。暂不重写表面图或新增全局求解器依赖。

- 每个小于10的区说明实际大小、相邻边界尝试、空间冲突/局部未找到改善/预算耗尽；不能统一写“几何必然”，除非有独立证明。
