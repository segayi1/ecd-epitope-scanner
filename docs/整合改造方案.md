## 1. Phase 1 · 后端修复与加固（先行，其他一切的地基）

### 1.1 已完成 · P0-1 FoldX 解析污染

`stability.py` 新增 `_parse_dif_fxout()`：显式定位 `Pdb\t` 表头行，之后只接受
首字段以 `.pdb` 结尾的数据行。`score_with_foldx` / `score_many_with_foldx` 改为共用。

实测验证（你的 binary + 你的 repaired 结构，LA231D）：
```
旧解析: [5.1, -0.597033, -0.780479]   median = -0.597   ← 表头行 "FoldX 5.1 (2011)" 被当成 ΔΔG=5.1
新解析: [-0.597033, -0.780479]        median = -0.6888  ← 正确
```

### 1.2 P0-2 · 分数来源与引擎名同源

`design.py`：引入显式 `score_origin ∈ {foldx, evoef2, proxy}`，与分数一起写入
`DesignRecord`。规则：

| 情形 | `stability_engine` | `score_origin` | `combined_stability_score` |
|---|---|---|---|
| FoldX BuildModel 成功 | `FoldX 5.1 BuildModel median ΔΔG` | `foldx` | kcal/mol 真值 |
| EvoEF2 成功（FoldX 缺席时） | `EvoEF2 mutant-minus-WT` | `evoef2` | EvoEF2 能量单位 |
| 两引擎都缺席 | `builtin structural-risk proxy` | `proxy` | 无量纲，前端必须显示"非 kcal/mol"徽标 |
| FoldX 在但解析失败 | `builtin structural-risk proxy (FoldX failed)` | `proxy` | 代理分 + `FOLDX_REVIEW_REQUIRED` |

禁止出现"`FoldX 5.1` + 代理分"的组合（这正是 `foldx_ecd` 产出里的现状）。

### 1.3 P1-3 · FoldX 批量失败改为 fail-loud + 插桩定位根因

**今日实测进展**（重要，修正对比报告里的初步推断）：
- 批量 BuildModel（5 组合 × 2 runs）在你的 binary + 你的 repaired 结构上**成功**，
  10 行数据全部解析正常；
- 在**无 rotabase.txt 的干净临时目录**里也成功——FoldX 会自行在工作目录生成
  `rotabase.txt` 与 `molecules/`，所以"缺 rotabase"假设不成立；
- 传给 `design_regions` 的 `structure_for_energy.pdb` 是合法的 ECD-only PDB。

即：解析器、二进制、批量格式、输入结构**逐项单独验证都正常**，
但整条流水线跑出来全是 None。根因需要插桩实跑定位（怀疑方向：当时代码版本
与现在不同、或超时/子进程环境差异）。

改造：
1. `score_many_with_foldx` 返回值从 `list[float|None]` 升级为
   `list[FoldXResult]`，附带 `returncode / n_rows_parsed / stderr_tail / elapsed_s`；
2. 当**全部**构造都失败时，`design_regions` 直接把作业置为
   `ERROR_FOLDX_ENGINE`（作业失败，需要看日志），而不是给每个区域挂
   `FOLDX_REVIEW_REQUIRED`（看起来像科学结论）；
3. `run_manifest.json` 新增 `stability` 块：binary 路径、文件版本、
   `RepairPDB/BuildModel` 调用参数、成功/失败计数、总耗时；
4. 修完后用 PD-L1（8AOM）实跑一遍 FoldX 全链路，把根因写回文档。

### 1.4 P1-4 · SASA 双路径口径统一

参考表 `MAX_ASA` 是 Tien 2013（DSSP 口径），两条求解路径都必须对齐：

```python
# Bio.PDB 回退：显式传入与参考表同源的半径（关键：O 1.52 → 1.40）
ShrakeRupley(probe_radius=1.4, n_points=960,
             radii_dict={"C":1.80,"N":1.60,"O":1.40,"S":1.85})

# FreeSASA：显式指定 NACCESS 半径配置
freesasa.Parameters({"algorithm": freesasa.ShrakeRupley,
                     "n-points": 960, "probe-radius": 1.4, "radii": "naccess"})
```

并把 `sasa_method`（含半径口径说明）写入 `run_manifest.json`。
验证：同一结构在 FreeSASA 可用/不可用两种环境下，rsasa ≥0.25 闸门选出的残基集合必须一致。

### 1.5 P2-5 · 单点门与组合门分离

| 闸门 | 现值 | 新值（建议，可配） |
|---|---|---|
| FoldX 单点 | ≤ +0.46 kcal/mol | 不变 |
| FoldX 组合 | ≤ +0.46（与单点共用） | **≤ +2.0 kcal/mol**（2–5 点组合），并对 ≤6 Å 邻近突变对计入 0.25×min(ΔΔGᵢ,ΔΔGⱼ) 的空间耦合修正 |
| 启发式预筛（无引擎时） | 每点 ≤1.45 代理分 | 不变，但组合总和阈值同样与单点分离 |

理由：实测 5 点组合的 FoldX 值普遍在 0.9–2.9 区间（本次批量实测：
2.53/2.87/1.45/1.71/2.19/2.20），用 0.46 一刀切等于宣布组合设计必然全灭。
阈值进 `request`/UI，可调。

### 1.6 回归测试

新增 `tests/test_foldx_parsing.py`：用今天实测捕获的真实 `Dif_*.fxout`
（含表头污染行）做 fixture，断言 `_parse_dif_fxout` 输出不含 5.1、
且批量分块中位数与手工计算一致。这是本类 bug 最有效的防回归手段。

### 2.2 生成器

新增 `exporting/offline_html.py`（或并入现有 `exporting.py`）：

1. 从作业目录读 `analysis.json / regions.json / designs.json / structure_for_energy.pdb`；

### 3.2 六步 walkthrough（数据全部来自你的后端）

| 步 | 标题 | 数据源 | 交互 |
|---|---|---|---|
| 1 | 表面可及性 | `residues.csv`（rsasa / side SASA 双闸） | 点击检查器；灰=未过闸 |
| 2 | 折叠耐受 | FoldX 单点门结果（`stability_class`、0.46 门） | 绿=neutral、红=destabilizing |
| 3 | 结构分区 | `regions.json` | 点区聚焦，其余变暗；显示膜远近与 PAE 徽标 |
| 4 | 功能界面 | `interface / glycan_shielded / salt_bridge` | 界面叠加开关（默认开，可关） |
| 5 | 推荐组合 | `designs.json` 每区一条组合 | 选中即高亮位点 + 底部序列联动 |
| 6 | 自主设计 | `POST /api/jobs/{id}/designs`（你已有的自定义组合） | 点珠子/点序列残基加组合，实时 FoldX 代理提示 |

着色语义沿用我刚完成的统一规则：
`已选突变 深红 > 界面叠加（可开关）> 分区饱和色 > 不可设计 灰`；
分区色即 `REGION_COLORS`，与 Mol*/3Dmol 两个渲染器共用同一套。

### 3.3 双渲染器

| | Beads（默认） | Cartoon |
|---|---|---|
| 引擎 | 3Dmol.js（`web/vendor` 已有） | PDBe Mol* 3.10.1（`web/vendor` 已有，静态资源测试已在跑） |
| 画法 | 每残基 Cα 球 + 语义色 | Mol* cartoon，残基按同语义色 |
| 拾取 | 3Dmol `setClickable/setHoverable` | Mol* interaction 事件 → 映射回 UniProt 编号 |
| 状态同步 | 两个渲染器共享同一份 `colorOf(uniprot_pos)` 与选中集合；切换时重建，不清空用户选择 | |

切换控件放在视口左上（与表示切换并列）；切换仅重建渲染层，右侧面板/序列栏不动。
风险点已在方案内注明：Mol* 拾取 API 与 3Dmol 不同，需写一层薄适配器（约 100 行），
用你现有 `browser_picking.mjs` 的思路做真浏览器断言。

### 3.4 底部序列栏

- 数据源：`designs.json` 的 `mutant_ecd_sequence / mutant_coding_sequence`（每区一条），
  第 6 步自定义组合时由后端 `apply_mutations + coding_fragment` 实时返回；
- WT 行始终显示 canonical ECD（`ecd_start–ecd_end`）；
- 突变位点高亮：色块 + hover 显示 `A215D (FoldX +0.31)`；
- 四个复制按钮：WT 蛋白 / WT CDS / 突变蛋白 / 突变 CDS；
- 复制成功用现有 toast；`navigator.clipboard` + `execCommand` 兜底。

### 3.5 中英文切换

- `web/i18n/{zh,en}.json` 静态字典，全部 UI 文案走 `t(key)`；
- 切换按钮在顶栏，`localStorage` 持久化，默认中文；
- 后端科学结论（`rationale / warnings`）保持英文原文（学术惯例），
  UI 负责在旁边给出中文说明文案（字典里配）；
- 导出离线 HTML 时把当前语言快照进去（`?lang=` 决定）。
